# Overlai 要件定義書（コンテストデモ版）

**目的：ユメカタリ 2026 開発部門の「デモ動画」で成立する最小構成を、限られた時間で完成させる**

---

## 0. 大前提

提出物は **作品概要書 ＋ デモ動画 ＋ ピッチ動画（1分）**。
審査されるのは「製品として完成しているか」ではなく、**技術力・実装力・実用性・社会的インパクト**です。

したがって設計方針は1つ。

> **デモ動画に映らない機能は、作らない。**

ログイン、DB、登録フロー、通知。これらは映像に映りません。**全部捨てます。**

---

## 1. デモで見せる1本の流れ（これが仕様のすべて）

```
[1] マイストック画面を開く
      └ 家にあるもの（処方薬・市販薬・化粧品）が一覧で並んでいる
              ↓
[2] 「スキャン」を押し、店頭の商品にカメラをかざす
      └ 実際は商品の成分表示を撮影
              ↓
[3] AIが成分を読み取る（ローディング1〜2秒）
              ↓
[4] 判定カードが出る
      🟡「家に同じ成分があります」 ← 1本目
      🔴「使用中のステロイドと相性注意」 ← 2本目
              ↓
[5] 「根拠を見る」を押すと、判定理由と該当成分が展開
```

**この5ステップが動けば、デモ動画は撮れます。** 逆に、これ以外は不要です。

---

## 2. 実装しないもの（明示的に捨てる）

| 機能 | 理由 | デモでの代替 |
| :--- | :--- | :--- |
| ユーザー登録・ログイン | 映らない | なし（単一ユーザー前提） |
| データベース | 映らない | シードJSON ＋ localStorage |
| 医療用QRコード（JAHIS）読み取り | 実装重い・仕様調査に時間がかかる | ストックに最初から入っている状態にする |
| レシート一括登録 | 映らない | 同上 |
| 服用カレンダー・通知 | 映らない | なし |
| JANコード→商品DB照合 | **日本に公式DBが存在しない** | 成分表示の直接撮影で回避（後述） |
| 塗る順序ナビ | 時間があれば | 静止画のモックを1枚だけ用意 |

**特に重要なのがJANコードの扱いです。** 化粧品のJAN→全成分の公式データベースは日本に存在しません。なので**バーコードではなく、パッケージの成分表示を直接撮影する**設計にします。これは妥協ではなく、**生成AIだからできる正攻法**であり、ピッチでもそう説明できます。

## 3. 画面要件（3画面のみ）

### 画面1：マイストック

- カテゴリ別のリスト表示（処方薬 / 市販薬・サプリ / スキンケア / ヘアケア）
- 各アイテム：商品名、主要成分（2〜3個をタグ表示）、残量 or 開封日
- **デモ用に7〜8件をシードデータで用意しておく**
- 右下に「スキャン」ボタン（FAB）

**シードデータ例（この構成なら黄も赤も出せる）**

| 商品名 | カテゴリ | 主要成分 | 状態 |
| :--- | :--- | :--- | :--- |
| ロキソニン内服薬（処方） | 処方薬 | ロキソプロフェンナトリウム | 残8回分 |
| イブA錠 | 市販薬 | イブプロフェン, アリルイソプロピルアセチル尿素 | 残12錠 |
| ヒルドイドローション（処方） | 処方薬(外用) | ヘパリン類似物質 | 使用中・顔 |
| ステロイド外用薬（処方） | 処方薬(外用) | ベタメタゾン吉草酸エステル | 使用中・顔 |
| ◯◯美容液 | スキンケア | ナイアシンアミド | 開封2ヶ月 |
| △△化粧水 | スキンケア | グリセリン, BG | 開封1ヶ月 |
| □□シャンプー | ヘアケア | ココイルグルタミン酸TEA（アミノ酸系） | 使用中 |

### 画面2：スキャン

- カメラ起動（`getUserMedia`）または画像アップロード
- 撮影 → 送信 → ローディング表示
- **保険：カメラが不安定な場合に備え、撮影済み画像を選ぶモードを必ず用意する**（本番デモで最も事故が起きる箇所）

### 画面3：判定カード

- 3色のシグナル（🔵🟡🔴）を大きく表示
- 見出し（例：「買わなくて大丈夫です」「注意が必要です」）
- スキャンした商品の検出成分
- 該当する自宅アイテム（カード形式で表示）
- **「根拠を見る」でアコーディオン展開** → 判定理由の文章
- **「薬剤師・皮膚科に相談」ボタンを常設**（安全設計のアピールになる）

## 4. AI処理の仕様

**2段階に分けます。** 1回で全部やらせると精度が落ち、デモで事故ります。

### ステップ1：成分抽出（画像 → 構造化）

画像を Vision で読み、以下のJSONのみを返させる。

```json
{
  "product_name": "検出した商品名（不明なら null）",
  "category": "市販薬 | スキンケア | ヘアケア | サプリ | 不明",
  "form": "錠剤 | 化粧水 | 乳液 | クリーム | 軟膏 | シャンプー | 不明",
  "ingredients": ["成分名1", "成分名2", "..."],
  "confidence": "high | medium | low"
}
```

プロンプト要点：
- 「JSONのみを返す。前置き・Markdownのコードフェンス禁止」
- 「読み取れない文字は推測せず省略する」
- 「全成分表示は記載順（配合量の多い順）を保持する」

### ステップ2：判定（商品 ＋ 在庫 → シグナル）

ステップ1の結果と、マイストック全件をJSONで渡す。

```json
{
  "signal": "blue | yellow | red",
  "headline": "20字以内の見出し",
  "summary": "1〜2文の説明",
  "matched_item_ids": ["id1", "id2"],
  "reasons": [
    {
      "type": "成分重複 | 効能重複 | 刺激リスク | 吸収阻害",
      "ingredient": "該当成分名",
      "detail": "なぜそう判定したかの説明",
      "related_item": "自宅アイテム名"
    }
  ],
  "consult_recommended": true
}
```

**判定ルール（プロンプトに明記）**

| シグナル | 条件 |
| :--- | :--- |
| 🔴 red | 在庫の処方薬（内服・外用）との併用でリスクがある成分を含む |
| 🟡 yellow | 在庫に同一成分、または同効能のアイテムが存在する |
| 🔵 blue | 上記いずれにも該当しない |

**安全のための制約（必ずプロンプトに入れる）**

- 断定表現を使わない。「〜の可能性があります」で統一する
- 診断・治療方針の提示を行わない
- 判定理由には必ず具体的な成分名を含める（根拠なき警告を出さない）
- red と判定した場合、`consult_recommended` を必ず true にする

**この制約セットは、そのまま概要書の「安全性設計」の章に転記できます。** 審査員に効きます。

## 5. 技術構成（推奨）

| 層 | 選択 | 理由 |
| :--- | :--- | :--- |
| フロント | Next.js (App Router) + TypeScript + Tailwind | スマホブラウザで動けばデモ映像は「アプリ」に見える |
| AI | Anthropic API（`claude-sonnet-4-6`）Vision | 画像→JSON構造化が安定。APIキーはサーバー側のRoute Handlerに置く |
| データ | シードJSON ＋ localStorage | DB不要。リセットも簡単 |
| デプロイ | Vercel | 数分で公開でき、実機で開ける |

**Route Handler を必ず経由してください。** クライアントから直接APIを叩くとキーが露出します。

**代替**：React Native / Expo が手に馴染んでいるならそちらでも構いません。ただしビルドと実機確認に時間を取られるので、**残り時間が24時間なら Web を強く推奨**します。

## 6. 作業順序（詰まったときに切る順に並べてあります）

1. **判定カードのUI**（ハードコードしたダミーデータで表示）← 最優先。ここだけあればデモ映像の山場は撮れる
2. **マイストック画面**（シードJSON表示）
3. **ステップ2のAI判定**（画像なしで、テキストの商品情報から判定）
4. **画像アップロード → ステップ1の成分抽出**
5. **カメラ起動**
6. Vercelデプロイ
7. 塗る順序ナビの静止画モック（余力があれば）

**5番以降は落としても、デモ動画は成立します。** 撮影済み画像を選ぶ形でも「スキャンして判定が出る」流れは映せます。

---

## 7. デモ動画の撮り方（実装と並行して準備する）

- **実際の商品を用意する。** 手持ちの市販薬と化粧水を撮るだけで、リアリティが跳ね上がります
- 黄と赤の**2本流す**。片方だけだと「重複チェッカー」に見えてしまい、企画の半分しか伝わりません
- 手ブレより**画面が読めることを優先**。スマホは固定して撮る
- AI応答の待ち時間は編集でカットしてよい（ただしピッチで「1秒」と言うなら誇張しすぎない）
- **録画は必ず前もって1本撮っておく。** 締切直前に一発撮りしようとして失敗するのが最も多い事故です

---

## 8. 概要書に書くべき技術ポイント

実装したら、以下を概要書に必ず書いてください。技術力の評価軸に直結します。

- **2段階のAIパイプライン**（成分抽出 → 在庫照合判定）にした理由：単一プロンプトでは精度が出ず、また抽出結果をユーザーが検証できないため
- **JANコードではなく成分表示を直接読む設計**にした理由：外用薬×化粧品の相互作用DBが日本に存在せず、非定型な表示を解釈できる生成AIでしか実装できない領域だから
- **ハルシネーション対策**：判定理由に必ず成分名を含めさせ、根拠を利用者が確認できる形にした
- **薬機法への配慮**：断定表現の排除と相談導線の常設をプロンプトレベルで制約している
