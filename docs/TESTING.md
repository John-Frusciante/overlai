## 0. まず `npm run check`（30秒）

コードを触ったら最初にこれを通す。型・lint・自動テスト（75件）がまとめて走る。

```bash
npm run check
```

テストだけなら `npm test`。TypeScript を CommonJS へ落として `node --test` に渡すだけで、
追加の依存もテストランナーの設定もいらない（`tsconfig.test.json`）。

見ているのはルールベースの部分と、AGENTS.md に書いてある決まりごと。

| ファイル | 何を確かめるか |
| :--- | :--- |
| `tests/knowledge.test.ts` | 全項目に出典が付いているか。代表的な組み合わせを引けるか |
| `tests/verify.test.ts` | 辿れない理由を落とすか。シグナルを書き換えないか |
| `tests/routine.test.ts` | 剤形の並び順。手で決めた並びの優先。区分の名前の検証 |
| `tests/cleanser.test.ts` | 肌質5値 × 頭皮4値 × 系統4種の**全組み合わせ**に判定が出るか |
| `tests/seed.test.ts` | 処方の内服に NSAIDs が無いか。🟡デモを崩す薬が入っていないか |
| `tests/request.test.ts` | 端末から来る値の検証（長さ・件数・想定外の値） |
| `tests/image.test.ts` | ガイド枠を映像の座標へ移す計算 |
| `tests/guard.test.ts` | 別オリジン・curl を断るか。開発中は素通りするか |

**テストで確かめられないもの**は下の A 以降に並べてある。実機・実物・人間の判断が要るもの、
そしてAIの出力（判定の中身）はここには入らない。

### 用意するもの
- 手持ちの**市販薬**を1つ（鎮痛薬・胃薬など何でも）

### 手順
1. スマホで https://overlai-delta.vercel.app/ を開く
2. 下部中央のスキャンボタン → カメラが起動
3. **パッケージの成分表示**（「成分・分量」「全成分」の欄）を枠に入れて撮影
4. 判定が出るまで待つ（9〜11秒）
5. **「根拠を見る」を開いて、読み取られた成分名が正しいか確認する**

### 確認すること

| 項目 | 見るところ |
| :--- | :--- |
| 成分名が正確か | 判定カード上部の成分タグ。誤字（「いブプロフェン」など）が無いか |
| 商品名が合っているか | 成分タグの上 |
| 判定が納得できるか | 色・見出し・要約 |
| 所要時間 | カード下部に「判定にかかった時間 ◯秒」が出る |

### 失敗したときの対処

| 症状 | 対処 |
| :--- | :--- |
| 「成分表示を読み取れませんでした」（422） | 明るい場所で、成分表示に**寄って**撮り直す。影と光の反射を避ける |
| 成分名が一部間違っている | 別の角度・距離で再撮影。それでもダメなら、その商品はデモに使わない |
| ボトルの曲面で読めない | ラベルの平らな部分を正面から。箱があれば箱の成分表示を撮る |
| どうしても通らない | `?demo=` のモックに切り替えて撮影する（§D） |

```

   ↓ ストックを追加
```

### D-1. プロバイダのフォールバック

学校配布のプロキシが止まったとき、Gemini に落ちて処理が続くか。本番では Azure が生きている限り Gemini は呼ばれないので、**ローカルでキーを壊して確認する**。

```bash
# Azure を無効にして Gemini だけで起動する
AZURE_PROXY_KEY= npm run dev

# 成分表示の画像を送る（実物の写真を base64 にして payload.json に入れておく）

  -H 'Content-Type: application/json' --data-binary @payload.json
```

`provider` が `gemini` になり、抽出と判定が両方返れば成功（実測 13.9〜30秒）。

チェーンが順に落ちること自体を見るなら、**両方を無効なキーにして**ログを読む。

```bash
AZURE_PROXY_KEY=invalid GEMINI_API_KEY=invalid npm run dev
```

```
[extract] azure 失敗 (auth) Error: 403 ...
[extract] gemini 失敗 (auth) Error [ApiError]: {"error":{"code":400,...
[analyze] 認証エラー: APIキーを確認してください
```

この順に出れば、チェーンは意図どおり回っている。

> **注意**: Gemini の無料枠は 5 RPM。`curl --retry` を付けるとHTTPエラーにもリトライがかかり、数回で枠を使い切る。**リトライは付けずに1回ずつ叩くこと。**

## G. ルーティン機能の確認（5分）

順序はルール、言葉はAIという切り分けが崩れていないかを見る。

### G-1. 服薬設定

1. `/stock/new` で剤形に「錠剤」を選ぶ → **服薬の欄が現れる**
2. 飲むタイミングに「朝」「夜」、1回量に 1、残量に 28 を入れて保存
3. `/routine` の「今日のお薬」に並ぶ。**朝と夜のボタンだけが出る**（昼は出ない）
4. 「朝」をタップ → 残薬が 27 に減る。もう一度タップすると 28 に戻る
5. 一覧からその項目をタップ → 編集 → **入力した値が初期値として入っている**
6. 剤形を「化粧水」に変えて保存 → 服薬の欄が消え、「今日のお薬」からも外れる

服薬設定が1件も無い状態（`/` の「編集 → 初期化」の前後）でも、見出しと設定への導線が出ることを確認する。

### G-2. 肌質・頭皮の反映

1. `/profile` で頭皮を「脂性」に設定 → シャンプーの下のコメントが「合いやすい傾向」側に変わる
2. 「乾燥」に変える → 同じシャンプーで「刺激になる可能性」側に変わる

4. 石鹸系のシャンプー（`石ケン素地` を含むもの）を登録しても頭皮の設定が効く

### G-3. AIの一言

1. `/routine` を開く → 「今日の組み合わせについて」にスケルトンが出て、数秒後に文章が入る
2. **リロードする → 即座に表示される**（ネットワークタブに `/api/routine` が出ないこと）
3. 「朝」のチェックを付け外しする → **再生成されない**（残量は署名に含めない）
4. ストックを1件追加する → 次に `/routine` を開いたときに作り直される
5. `.env.local` のキーを壊して開く → **一言だけが出ず、順序と理由は普通に表示される**

5 は「解説が落ちても画面は成立する」ことの確認。エラー表示は出さない仕様なので、出ていたら実装がずれている。

### G-4. 手動並べ替え

1. 「お風呂上がりに塗る順番」の「並べ替え」を押す → 各ステップに ↑↓ が出る
2. 軟膏を1つ上へ動かす → 番号が振り直され、見出しの説明が「自分で並べた順です」に変わる
3. リロードしても並びが保たれる
4. 新しくクリームを登録する → **手動の並びに割り込まず、末尾に追加される**
5. 「剤形どおりの順に戻す」→ 元の並びと説明に戻る
6. 並べ替えた直後に `/routine` を開き直すと、**AIの一言が作り直される**（並び順は署名に含まれる）

その項目の剤形を変えて「お風呂で洗う」に移すと、移した先で先頭に割り込まないことも確認する。

### G-5. ルーティンの区分を作る・消す

1. `/stock/new` の「毎日のルーティン」で「ルーティンを追加」→「朝のスキンケア」を作る → **そのまま選択された状態になる**

3. `/routine` に「朝のスキンケア」のセクションが出て、**洗顔 → 化粧水 → 乳液**の順に並ぶ
4. 画面下の「自分で作ったルーティン」に件数つきで出る
5. `×` → 移動先に「どこにも入れない」を選んで削除 → セクションが消え、**在庫は残っている**

### G-6. 肌質の自由記述

### G-7. 設定画面

1. マイストックの右上が「**設定**」になっている（以前の「編集」ではない）
2. タップ → `/settings` に飛ぶ
