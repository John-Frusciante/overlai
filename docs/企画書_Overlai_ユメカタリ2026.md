# Overlai

### 買う前に、家の棚を重ねて見る。

## 「その商品がいいかどうか」ではなく、 「あなたの家に、もうあるかどうか」を判定する。

**ユメカタリ 学生生成AIコンテスト 2026 応募企画書**

> **名称について ── Overlai**
> Overlay（重ねる）＋ AI。読みは「オーバーレイ」。
> このプロダクトには「重ねる」が3つあります。
> ① 店頭の商品に、**自宅の在庫を重ねて**照合する
> ② 化粧水の上に薬を**重ねて塗る**（順序ナビ）
> ③ 成分が**重なっている**（重複警告）
> 機能の3本柱が、そのまま名前になっています。

## 1. 課題 ── 判断が、いつも足りない場所

### 場面1：ドラッグストアの鎮痛薬の棚の前

> 頭痛薬を切らした気がして、棚の前に立つ。
> でも、この前もらった処方薬に同じ成分が入っていないか、分からない。
> 家の救急箱にまだ残っていた気もするけれど、思い出せない。
> 結局、買う。家に帰ると、同じ薬が8回分残っている。

### 場面2：化粧水の棚の前

> 皮膚科でステロイドの塗り薬をもらっている。
> 目の前の化粧水は、その薬と一緒に使って大丈夫なんだろうか。
> パッケージには「敏感肌の方にも」と書いてある。
> でも、それは「薬を塗っている肌」を想定した言葉ではない。
> 判断材料がないまま、雰囲気で買う。

**（※ここに応募者自身の体験を3〜4行で差し替える）**

どちらも、**判断に必要な情報は全部「家」にある**のに、その情報を店頭に持ち出せないことが原因です。

## 2. なぜ、これだけアプリがあるのに解決されないのか

原因は「誰も気づいていないから」ではありません。**既存サービスは全員、"商品側"のデータベースで戦っているから**です。

| サービス | 持っているデータ | 答えられること | 答えられないこと |
| :--- | :--- | :--- | :--- |
| コスメ成分アプリ（Yuka等） | 化粧品200万点の全成分 | この商品は安全か | もう持っているか |
| お薬手帳アプリ（EPARK等） | 調剤履歴 | 飲み合わせは大丈夫か | 棚の商品と被るか |
| 小売アプリ（マツキヨ等） | 自社全商品・口コミ | この商品の評判は | 家の在庫と重複するか |

商品データベースをどれだけ大きくしても、**「あなたの家に、もうある」だけは絶対に言えません。**

さらに構造的な問題があります。**産業が縦に割れていること**です。

- 飲む薬 → 製薬・調剤薬局の領域
- 塗る化粧品 → 化粧品メーカーの領域
- 洗うもの → 日用品メーカーの領域

**処方された塗り薬は、このどこにも居場所がありません。** 医療の側から見れば「外用薬」、生活の側から見れば「肌に塗るもの」。両産業とも、互いの領域を見に行く動機を持たないまま今に至ります。

だから「ステロイド軟膏と、この化粧水」を並べて判断してくれる道具が、存在しません。

**でも、それを全部使う体は、ひとつしかない。**

## 3. 解決 ── 判定の基準を、商品から「その人の家」へ

### 中核機能：スマートスキャナー（店頭モード）

**店頭で商品のバーコード、または成分表示にカメラをかざす。1秒で、自宅の在庫データと突合した判定が出る。**

```

┌─────────────────────────┐
│  🟡  買わなくて大丈夫です      │
│                             │
│  この商品の主成分：            │
│  イブプロフェン 150mg         │
│                             │
│  家にある同成分：              │
│  ・処方薬「◯◯錠」 残 8回分    │
│  ・市販の△△ 残 12錠          │
│                             │
│  ▸ 根拠を見る                │
└─────────────────────────┘
```

```
📷  スキャン中...

┌─────────────────────────┐
│  🔴  注意が必要です            │
│                             │
│  この化粧水に含まれる：        │
│  エタノール／サリチル酸        │
│                             │
│  現在お使いの処方薬：          │
│  ステロイド外用薬（顔）        │
│                             │
│  薬を塗っている部位への使用は   │
│  刺激になる可能性があります。   │
│  皮膚科でご確認ください。      │
│                             │
│  ▸ 根拠を見る  ▸ 薬剤師に相談 │
└─────────────────────────┘
```

**3色シグナル**

| | 意味 | 例 |
| :---: | :--- | :--- |
| 🔵 **青** | 手持ちにない有用成分、または目的別の買い分けとして妥当 | 普段はアミノ酸系シャンプー、これはワックス落とし用 |
| 🟡 **黄** | 同一成分・同効能が自宅に存在。買わなくていい | 同じ鎮痛成分が残8回分／ナイアシンアミドが手持ち美容液と重複 |
| 🔴 **赤** | 手持ちの処方薬・常用品との併用でリスクや強い刺激 | ステロイド外用中の肌へのアルコール系化粧水 |

判定は断定ではなく、**根拠成分と相談導線を必ず添えて提示**します。

## 4. これを支える2つの機能

店頭判定は、**家の状態が分かっていて初めて成立**します。

### ① 自宅ストック管理

救急箱の薬、サプリ、洗面所のコスメ、風呂場のシャンプー・詰め替えを一覧化。残量・開封日・使用期限を管理し、市販薬の期限だけでなく、コスメ・ヘアオイルの酸化目安（開封後3〜6ヶ月）も通知します。

登録は3経路。**「まず全部登録してください」を要求しない設計**が鍵です。

- 処方薬 → 調剤明細の医療用QRコード（JAHIS標準規格）を一括読み取り
- 市販薬・コスメ → JANコード or 成分表のカメラ読み取り
- まとめて → レシート撮影で複数商品を一括登録

### ② 洗う・塗るステップナビ

在庫が入っていれば、店頭判定だけでなく**毎日の使い方**まで案内できます。ここが「買うときだけのアプリ」で終わらせないための機能です。

- **インバス**：シャンプー → トリートメント → 洗顔 → ボディソープの順序案内（トリートメント残渣による背中ニキビの防止）
- **アウトバス**：処方外用薬（軟膏・クリーム・ローション）× 市販スキンケア（導入液・化粧水・美容液・乳液）× ヘアケアを、**基剤と浸透度に応じて1本の列に自動ソート**
- **成分バッティング警告**：レチノール × 高濃度ビタミンC、AHA/BHA等
- **洗浄基剤の相性判定**：アミノ酸系・高級アルコール系・石鹸系 × 肌質・頭皮状態

## 5. なぜ生成AIが必要か

この判定は、単純なルールテーブルでは解けません。

**（1）表示フォーマットが非定型**
市販薬の成分表示、化粧品の全成分表示、調剤明細。書式も用語も企業ごとにバラバラで、従来のOCR＋辞書照合では読み取れませんでした。生成AIは、これを剤形・基剤・主成分という構造に解釈できます。

**（2）判定基準が「組み合わせ」で決まる**
同じサリチル酸でも、健康な肌なら問題なく、ステロイド外用中の肌なら刺激になる。**商品単体の属性ではなく、その人の在庫全体との関係**で結論が変わります。組み合わせは無数にあり、事前に表を作り切ることは不可能です。

**（3）公式データベースが存在しない領域を扱う**
内服薬の相互作用はPMDA添付文書に明記され、商用DBもあります。しかし**「外用薬 × 化粧品」の相互作用データベースは日本に存在しません**。ここは成分の性質からの推論が必要な領域であり、だからこそ20年間空白のまま残されてきました。

そのため出力は断定を避け、**根拠成分を必ず併記し、専門家への相談導線を常設**します。

## 7. 競合比較

| 比較項目 | お薬手帳アプリ | コスメ成分アプリ | 小売アプリ | **本企画** |
| :--- | :--- | :--- | :--- | :--- |
| 管理対象 | 処方薬のみ | 市販コスメのみ | 自社商品 | **処方薬＋市販薬＋サプリ＋コスメ＋バス用品** |
| 判定の基準 | 薬同士 | 商品の安全性 | 商品の評判 | **その人の自宅在庫** |
| 「もう持ってる」 | × | × | × | **○** |
| 外用薬 × 化粧品 | × | × | × | **○** |
| 洗う・塗る順序 | × | 化粧品内のみ | × | **処方薬を含めた完全統合** |
| 利用シーン | 通院時 | 購入検討時 | 買い物時 | **買い物＋朝晩のケア（毎日）** |

**現状スペック（2026年9月時点の公開情報）**

- EPARKお薬手帳：利用者600万人超（2025年3月時点）。飲み合わせチェックを実装済み（処方薬×市販薬、薬×食品まで対応）。ただし**内服のみ**
- Yuka：ユーザー8,000万人、化粧品200万点を全成分分析しカラーコードで評価。ただし**商品単体の安全性評価**で、処方薬は対象外
- マツキヨココカラ公式アプリ：商品スキャンと調剤履歴管理を1アプリに統合済み。ただし**自社商品情報の提示**であり、自宅在庫との突合は行わない
- スキンケア記録アプリ：重ね順の自動整理と成分警告を実装済み。ただし**化粧品の中だけ**で完結

**空いているのは「自宅在庫を判定基準にする」という一点だけです。**

## 8. 安全性と法務の設計

医療に隣接するサービスとして、以下を前提に置きます。

- **診断・治療判断は行わない。** 提示するのは一般的な成分情報であり、疾患の診断やリスクの断定は行わない
- **根拠を必ず併記する。** AIの出力単独ではなく、添付文書・製品表示の該当箇所を同時表示し、利用者が検証できる形にする（生成AIのハルシネーション対策）
- **専門家への導線を常設する。** 赤判定には必ず「皮膚科・薬剤師に相談」を併置
- プログラムの医療機器該当性については、記録・情報提示の範囲に留める設計とし、機能追加時に都度確認する（厚生労働省ガイドライン）

## 9. 社会的インパクト

**（1）過剰摂取・重複購入の防止**
市販の鎮痛薬・総合感冒薬は成分が重複しやすく、処方薬との併用による過量摂取リスクが指摘されています。「家に何があるか」が分かるだけで、この事故の相当数は起きません。

**（2）外用薬アドヒアランスの改善**
皮膚疾患の治療では、薬そのものより「正しく使えているか」がボトルネックになります。診察の3分に収まらない指導を、家庭まで届けます。

**（3）無駄買いの削減**
使い切らないまま期限を迎えるコスメ・市販薬は、家計にとっても環境にとっても損失です。

## 10. 市場性とロードマップ

### ビジネスモデル
- 基本無料 / 登録数無制限・履歴機能でサブスクリプション
- 皮膚科・調剤薬局への導入（服薬指導の補助ツール）

※ 小売への送客モデルは「重複警告＝売上減」の利益相反が生じるため、**あえて採らない**

### ロードマップ

- **Phase 1** 在庫登録（QR・JAN・レシート）＋ 店頭3色判定（内服の重複のみ）
- **Phase 2** 外用領域へ拡張 ── 処方外用薬 × 化粧品の相性判定、塗る・洗う順序ナビ
- **Phase 3** 使用期限・残量管理、家族アカウント
- **将来** マイナポータル医療保険情報取得APIとの連携により処方情報を自動取得（同APIは既に民間267事業で利用実績あり）。トラブル発生時に直近の新規アイテムから原因成分を絞り込む逆引き機能
