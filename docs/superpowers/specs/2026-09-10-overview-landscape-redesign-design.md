# Overlai作品概要書 横向き再設計

## 目的

審査員がOverlaiを知らない状態でも、2〜3分で次の内容を理解できる作品概要書にする。

- 何に困ったことが開発の出発点だったか
- Overlaiが二つの問題をどうまとめて解くか
- 店頭から購入後まで、どのように使うか
- 既存の管理アプリと何が違うか
- AIをどこに使い、安全性をどう支えているか

主な閲覧環境はパソコンとする。画面に合わせた16:9横向きで作成し、編集用PPTXとPowerPointから書き出した提出用PDFを用意する。

## 読者と読了時間

読者は、Overlaiや開発背景を知らないコンテスト審査員である。最初から順番に読む場合は2〜3分、タイトルと主要図だけを追う場合は1分程度で要点が分かる密度を目指す。

本文は最低16pt、重要な説明は18〜22pt、ページタイトルは30pt以上を基準とする。小さな補足を増やして情報を詰め込まず、各ページの主役を一つに絞る。

## 全体構成

### 1. 私たちが困っていたこと

井上の「同じような効果の風邪薬が家に複数あった」という経験と、杉本・濱田の「ステロイド外用薬と化粧品の相性や塗る順番が分からなかった」という経験を左右に置く。

二つの経験を「でも、それを全部使う体は、ひとつしかない。」という着想へ合流させる。応募者名、学校名、実機QRコードは上部にまとめ、原体験より目立たせない。

### 2. 二つの問題を一つの在庫で解く

薬、サプリ、化粧品、ヘアケアを一つの在庫として扱う考え方を示す。店頭の商品を家の在庫へ重ねることで、重複、組み合わせ、使う順番を確認できることを一文で定義する。

ここでは個別機能を網羅しない。Overlaiが「商品だけを評価するアプリ」ではなく、「その人の家にあるものとの関係を見るアプリ」であることを伝える。

### 3. 店頭から購入後までの使い方

実際のアプリ画面を中心に置き、次の流れを横一列で示す。

1. 家にある薬や化粧品を登録する
2. 店頭で商品の成分表示を撮影する
3. 家の在庫と照合する
4. 青・黄・赤と根拠を確認する
5. 購入後も塗る順番や服薬記録に在庫を生かす

説明用の模式図だけで終わらせず、判定理由と塗る順番の実画面を使う。原体験がどの操作で解決されるかを確かめられるページにする。

### 4. 家の在庫で答えが変わる実証

御岳百草丸を同じ条件で撮影した結果が、在庫の有無によって青から黄へ変わることを左右比較で示す。

- 在庫へ追加していない場合：青「登録在庫との重複なし」
- 在庫へ追加した場合：黄「家にあります」

中央へ「商品は変えていない。変えたのは家の在庫だけ」と置く。この比較を作品の独自性を示す中心的な実証とする。3色の一般説明は短い凡例に留め、比較結果と競合させない。

### 5. AIの使い分けと安全設計

上段で、AIと決められたルールの役割を分けて示す。

- AI：成分表示の読み取り、店頭商品と在庫の関係の判定
- ルール：剤形に基づく塗る・洗う順番、使用期限、残量、服薬記録

AIの処理は「読み取り」と「判定」の二段階に分け、利用者が抽出結果を確認できることも示す。

下段には安全設計と検証結果を対応づけて置く。

- 薬の知識は出典と一緒に管理する
- 入力からたどれない成分を理由から除外する
- 赤判定の相談推奨をサーバー側で強制する
- 在庫は判定時だけ送信し、サーバーへ永続保存しない
- 診断や治療判断は行わない
- 実在5商品、代表3シナリオ計9回、自動テスト75件で確認した

## 視覚設計

白地と濃紺を基本にし、強調色は青、黄、赤の判定色へ限定する。判定色以外の装飾色は増やさない。

カードを均等に並べるだけの構成を避ける。原体験は左右で比べ、利用方法は横方向の流れで見せる。独自性は結果を比較し、安全設計は役割の対応関係で表す。ページごとに異なる視覚リズムをつくる。

QRコードは1ページ目だけに置く。ロゴ、ページ番号、短いフッターは全ページで位置を揃える。アプリ画面以外の文字、図形、線、矢印はPowerPoint上で編集できる要素として作成する。

## 成果物

- `docs/Overlai_作品概要書.pptx`：16:9横向き、5ページの編集用原本
- `docs/Overlai_作品概要書.pdf`：Microsoft PowerPointから書き出した提出用PDF

既存のHTML版は比較資料として残すが、提出物の原本にはしない。

## 検証

- PPTXのページ数、寸法、ファイル構造を検査する
- PowerPointでPDFへ書き出す
- PPTXとPDFの全ページを画像化して確認する
- 文字切れ、重なり、意図しない改行、画面画像の過度な切り抜きがないことを確認する
- タイトルだけを順に読み、原体験から安全性まで話がつながることを確認する
- `npm run check`を実行する
