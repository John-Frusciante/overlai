# Overlai

### 買う前に、家の棚を重ねて見る。

「その商品がいいかどうか」ではなく、**「あなたの家に、もうあるかどうか」**を判定する。

店頭の商品パッケージにカメラをかざすと、自宅の在庫データと突合して3色で判定します。

| | 意味 |
| :---: | :--- |
| 🔵 | 手持ちにない有用成分、または目的別の買い分けとして妥当 |
| 🟡 | 同一成分・同効能が自宅に存在。買わなくていい |
| 🔴 | 手持ちの処方薬・常用品との併用でリスクや強い刺激 |

## 技術構成

| 層 | 選択 |
| :--- | :--- |
| フロント | Next.js (App Router) + TypeScript + Tailwind CSS |
| AI | Anthropic API (`claude-opus-5`) Vision + 構造化出力 |
| データ | シードJSON + localStorage（DB不使用） |
| デプロイ | Vercel |

### 設計上の要点

- **2段階のAIパイプライン**（成分抽出 → 在庫照合判定）。単一プロンプトにしない理由は仕様書 §7.2
- **JANコードではなく成分表示を直接読む**。化粧品の公式成分DBが日本に存在しないため（§7.1）
- **APIキーはサーバー側の Route Handler のみで保持**（§10）
- **判定理由に必ず成分名を含める**ことをスキーマで強制（§7.4・§12）

## 開発の進め方

Issue は仕様書 §14 の作業計画に対応し、**下から切り落とせる順**に並んでいる。

```
#1 初期化 → #2 型・シード → #3 判定カードUI → #4 マイストック
                              ↓
                     #5 判定API → #6 成分抽出 → #7 画像アップロード → #10 デプロイ
```

| 優先度 | Issue | 位置づけ |
| :--- | :--- | :--- |
| `must` | #1 #2 #3 #4 #5 #6 #7 #10 | **これが揃えばデモは成立する**（クリティカルパス・約10時間） |
| `should` | #8 #9 | 加点。落としてもデモは撮れる |
| `low` | #11 #12 | 時間がなければ落とす |

**#3（判定カードUI）を早期に着手する。** ダミーデータで表示できた時点でデモ映像の山場は撮れるため、以降のタスクが遅れても最低限が確保できる。
